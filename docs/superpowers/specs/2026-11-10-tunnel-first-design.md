# 隧道优先重构 设计文档

日期：2026-11-10 · 状态：待批准

## 意图

初衷流程：公网机单文件部署 → 内网设备拿到 nfrc → 面板建隧道 → 面板给出一条启动命令 → 设备上执行 → 隧道即通。
现状把流程做反了：先「节点页生成加入码」接入设备，再回隧道页建隧道，且表单字段全平铺。
本次重构让**隧道成为唯一入口**：不存在的设备也能先建隧道，命令一跑，设备与隧道同时生效。

## 目标

1. 建隧道时可选「新设备」：提交后隧道进入「待接入」，面板给出绑定该隧道的 `nfrc join` 命令；设备执行后自动注册节点并激活该隧道。
2. 单服务器时隧道页不再出现「选服务器」中间层，直接进隧道列表。
3. 建隧道表单分级：必填只剩 协议 / 本地地址 / 本地端口 / 接入目标；域名、限速、配额、名称、远程端口收进「高级」。
4. 概览与隧道合并为一个页面（导航从 5 项变 4 项）：统计条内联在隧道页顶部。
5. 客户端零改动：`nfrc join <server> <code>` 协议、CLI 完全不变。

## 非目标 / 反目标

- 不把「下载客户端」包进启动命令（用户明确拒绝）；面板不新增下载托管。
- 不改 federation 多机纳管协议；远程服务器的隧道创建沿用现有远端 API。
- 不做 agent 上报监听端口的「真实地址建议」功能（表单里的假建议直接删掉）。
- 反目标：把加入码变成长期 token 写进客户端配置。

## 约束

- Go 1.26，服务端渲染面板（embed 模板 + 原生 JS），无 npm、无 CDN。
- 加入码仍为一次性、明文只存几分钟（auth 包现状），可吊销。
- 现有 e2e 脚本（scripts/e2e*.py）必须继续通过。

## 方案对比（已选定 A）

- **A. 隧道绑定加入码（选定）**：`JoinCode` 增加 `TunnelID`；隧道表单选「新设备」时铸造绑定码；`handleJoin` 兑换时创建节点并把 `Tunnel.NodeID` 指向它。客户端零改动，安全模型不变。
- B. 预生成节点 token：建隧道时发长期 token，客户端 `join --token`。否决：改客户端 CLI/协议，且长期凭据落在设备配置里，弱于一次性码。
- C. 只做 UI 精简、保留两段式。否决：不解决流程倒置，用户的初衷没实现。

## 数据与协议改动

- `internal/auth/auth.go:99` `JoinCode` 增加 `TunnelID string \`json:"tunnel_id,omitempty"\``。
- `internal/server/control.go:152` `handleJoin`：兑换成功创建节点后，若 `jc.TunnelID` 非空**且目标隧道 `NodeID==""`**（绝不重绑已接入的隧道），则在同一个 `st.Update` 里把隧道绑到新节点。无需显式 bump revision 或主动推送：`store.Update` 每次自增 revision（store.go:206），且新节点收到 Welcome 后才发起 handleControl，其首个 configFrame（control.go:295）就已包含该隧道。
- `internal/api/types.go:116` `JoinCodeRequest` 增加 `TunnelID`；隧道创建响应在未指定节点时附带 join 块（code/expires/command）。
- 隧道新增状态 `awaiting`（待接入）：`NodeID == ""` 且已创建。删除待接入隧道时作废其绑定码。

## 面板改动

- `templates/tunnel_form.html`：
  - 节点选卡末尾加「＋ 新设备」选项（值 `new`）。
  - 必填区：协议（分段选择，默认 TCP）、本地地址、本地端口、接入目标。
  - 「高级」折叠（`<details>`）：名称（留空自动生成，如 `tcp-8080`）、远程端口（留空=自动分配，租约逻辑自动走，删除「获取端口」按钮）、绑定域名（仅 HTTP）、带宽限速、月流量配额、启用开关（默认开）。
  - 删除硬编码 `SUGGEST` 假数据与 combobox（`tunnel_form.html:254` 起）。
  - 选「新设备」提交后跳转隧道详情视图：显示完整命令 + 复制按钮 + 剩余时间 + 「重新生成」。
- `templates/tunnels.html`：单服务器时由 handler 直接 302 到 `?server=local`；多服务器保留卡片选择。待接入的隧道卡片显示命令摘要与状态 chip。
- 概览合并：`templates/overview.html` 的统计条移入 `tunnels.html` 顶部；删除 overview 页与导航项，`/nfr/overview` 302 到 `/nfr/tunnels`。导航变 4 项：隧道 / 节点 / 服务器 / 设置。
- `templates/nodes.html`：保留为管理页（改名/移除/新建隧道），顶部说明改为「设备也可以直接在新建隧道时创建」；独立的生成加入码保留（纯加机器路径）。

## 默认值与边界（实现者的裁量已定）

- 隧道绑定码默认 TTL 30 分钟（普通加入码仍 5 分钟），一次性、可吊销；表单/详情显示倒计时与重新生成。
- 待接入隧道在隧道列表正常显示（状态 chip「待接入」），计入「启用隧道」统计。
- 同一新设备要建多条隧道：第一条用「新设备」接入后，后续在表单里正常选该节点。
- federation 远端服务器上建隧道暂不支持「新设备」选项（界面隐藏该卡），后续版本再议。
- 「服务端本机」目标不受影响。

## 留给实现者

- 自动分配端口沿用现有租约实现（面板走 `POST /nfr/api/allocate`，handlers.go:699），表单提交时静默完成。
- 待接入状态在 `tcard`/`ocard` 的 `StatusKind` 映射：在 `tunnelStatus`（server.go:596）最上方加 `Awaiting` 分支，先于 NodeMissing 判断，新 kind 用 warn 色 + 「等待接入」。
- 待接入隧道的创建走内部路径：`buildTunnel`（service.go:206）的节点校验不放宽，新设备流程在同一 `st.Update` 里跳过该校验并铸造绑定码，防止普通 API 悄悄建出孤儿隧道。
- 端口立即绑定（已确认）：reconcile 不改，待接入期间端口监听、访问 502/关闭；设备接入后即通。
- 名称留空时服务端自动生成（如 `tunnel-<port>` 或 4 位随机），buildTunnel 的 name 校验不放宽。
- 概览合并后的隧道页顶部统计条：在线节点、启用隧道、入站/出站流量 四项（原概览的 stats 原样搬移）。
- 命令展示不新建详情模板：创建后 302 回隧道列表，待接入卡片内联展示命令 + 复制 + 倒计时 + 「重新生成」（重生成 = 删除旧码 + 铸新码，保持一次性）。
- 兑换时若隧道已被删除：节点照常创建，绑定静默丢弃，面板事件里提示「隧道已不存在」。
- 吊销 = 删除待接入隧道时同时删除其绑定码，不新增 REST 路由。
- federation 远端服务器永久隐藏「＋新设备」（JoinCodeRequest.TunnelID 字段远端忽略即可）。
- 删除 tunnel_form.html 的 SUGGEST/combobox（234-288 行），地址与端口用普通输入框。
- e2e 改动：scripts/e2e.py:200 断言「概览」改为「隧道」；新增用例：建待接入隧道 → 抓取命令 → nfrc join → 验证 NodeID 绑定与流量通路。
- 单服务器 302 已存在（handlers.go:178-190），仅需验证。
